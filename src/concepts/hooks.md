
# 钩子

`RegisterHook` 挂在游戏的 `UFunction` 上，有两条路径：

| 函数种类 | 钩在哪里 | 能看到哪些调用 |
|---|---|---|
| **蓝图函数**（脚本函数） | 引擎执行蓝图字节码的解释器（`ProcessLocalScriptFunction`） | **所有**调用：蓝图调蓝图、蓝图事件、委托触发、从 C++ 经 `ProcessEvent` 来的 |
| **原生函数**（C++ 实现的 `UFUNCTION`） | `ProcessEvent`，加上函数入口上的一个小垫片 | `ProcessEvent` 发起的调用，以及蓝图虚拟机直接发起的调用 |

蓝图虚拟机调原生函数时，参数还在调用方的字节码里。注册钩子时核心会在这个函数的入口放一个垫片：它用引擎自己的操作码表（`GNatives`，运行时定位）把参数求值到缓冲区，运行你的回调，再用同样的缓冲区调用原函数——所以前置回调里改参数**会生效**。

蓝图函数的参数在调用方已经求值好、放在栈帧里，所以前置回调里能读，也能在函数执行前**改**；后置回调里能读返回值，也能通过回调的返回值改写它。游戏的玩法逻辑几乎都是蓝图，这条路径覆盖了绝大部分你会想钩的函数，包括之前"蓝图内部调用钩不到"的那一类（例如 `ExecuteUbergraph_*` 和蓝图函数库里的函数）。

## 触发时机

- 前置回调（第 2 个参数）在函数执行**之前**触发，后置回调（第 3 个参数，可选）在函数执行**之后**触发。
- 前置回调里改 `params` 可以改变传给函数的参数值；后置回调里能读到输出参数。
- 回调可以通过**返回值**替换函数的返回值（在后置回调里返回，nil 表示不改）；**不能**取消调用。

## 函数必须已经存在

`RegisterHook` 注册时要在内存里找到这个 `UFunction`，找不到会抛错 `RegisterHook: function not found: ...`。所以挂蓝图函数时，它所在的类必须已经加载。如果类还没加载，可以先 [`LoadAsset`](../lua-api/global-functions/loadasset.md) 把它加载进来，或者用 [`NotifyOnNewObject`](../lua-api/global-functions/notifyonnewobject.md) 等它出现。

## 不能挂的

- 带**非 const 引用/输出参数**的原生函数：从蓝图发起的调用看不到（参数的值在调用方的变量里）。注册时会在日志里提示。
- 原生钩子最多 64 个函数；找不到操作码表时（不支持的游戏版本）只剩 `ProcessEvent` 路径。
- 原生钩子对字符串等参数的求值副本不会立即释放（每次调用泄漏几十字节），不要钩每帧调用的原生函数。
- 回调里（以及模组在 tick 里）自己发起的游戏调用不会再次触发钩子，避免递归。
- 对每帧调用上百次的函数（如 `Tick`）要特别小心：回调在游戏线程里同步执行。

## 清理

钩子带有模组标记：模组被禁用或重新加载时自动撤销，不需要手动 `UnregisterHook`。

## 出错

回调里的错误写进日志，不会影响游戏和其他钩子；但会计入该模组的错误数，累计 10 次模组会被自动禁用，见[模组生命周期](lifecycle.md)。

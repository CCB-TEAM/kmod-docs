
# 崩溃保护与安全模式

模组里的 Lua 报错会被捕获，但原生崩溃（写错属性、非法指针）会直接带走游戏。kmod 记录崩溃时正在运行什么，下次启动时据此处理，避免反复崩溃。

## 记录

游戏线程在运行模组的钩子、定时器、新对象回调、`main.lua`，或者挂载某个 pak 时，核心会记下"现在是哪个模组（或哪个 pak）"。崩溃处理程序把它写进 `kmod/boot/crash.mark`。

## 下次启动

| 情况 | 处理 |
|---|---|
| 崩溃时正在运行某个模组 | 该模组被**隔离**：不加载，状态显示 `not loaded: it crashed the game`，其他模组照常 |
| 崩溃时正在挂载某个 pak | 该 pak 被隔离，不再挂载 |
| 崩溃时没在运行任何模组（原因不明） | 记一次。**连续两次**原因不明的崩溃进入**安全模式** |
| 启动后没有撑到稳定就消失，且没有崩溃记录（被杀掉等） | 连续三次后进入安全模式 |

游戏正常运行 60 秒后，计数清零。

## 安全模式

安全模式下**不加载任何模组，也不挂载任何 pak**，游戏按原版运行。它会一直保持，直到你关掉它：

```
safe            查看状态：是否在安全模式、崩溃次数、被隔离的模组和 pak
safe off        离开安全模式，并立即重新加载模组、挂载 pak
unquarantine mod <模组id>      让被隔离的模组重新加载
unquarantine pak <pak 文件名>   让被隔离的 pak 重新挂载
```

在 Mods 页里把被隔离的模组重新启用，也会解除它的隔离。

## 文件

都在 `kmod/boot/`：`state.txt`（崩溃计数、是否安全模式）、`crash.mark`（上次崩溃时的活动）、`quarantine.txt`（被隔离的模组 / pak，以及你用 `paks off` 关掉的 pak）。要手动恢复，删掉这个文件夹即可。
